8.1 进阶路线图:接下来玩什么

板子现在跑着主线 U-Boot + Linux 6.18 + Debian 13,SD 卡启动、ssh 可达——这就是传说中的"能用"状态。往下怎么走?这里给出六个方向,每个都标注做什么、学什么、难度,先上一张总览,再逐个展开:

难度怎么读?主要看三件事:要不要写裸机代码(FSBL)、要不要装新工具链、出错时好不好回退。同一个方向,把第 06 章灌注救援亲手做过一遍的你和没做过的你,体感难度完全不同。

#方向难度一句话
一给 end0 钉死 MAC 地址入门半小时让板子每次以同一身份上线
二JTAG 启动模式入门把第 06 章的调试功夫变成日常救援通道
三PYNQ 镜像尝鲜入门厂商 demo 包里有现成的,刷卡即玩
四响亮 FSBL中等让启动过程开口说话,静默故障无处遁形
五QSPI 启动中等偏上启动链写进板载闪存,向产品化再进一步
六PL 开垦(FPGA 逻辑篇)进阶请出 Vivado,开垦 Zynq 姓"F"的那一半

方向一:给 end0 钉死 MAC 地址(难度:入门)

  • 做什么:写一个 systemd 的 .link 文件,给 end0 固定 MACAddress——文件放 /etc/systemd/network/ 下,Match 段按 Name=end0 匹配,Link 段写死 MACAddress,机制细节 man systemd.link 讲得最全;
  • 学什么:systemd-udevd 的 .link 匹配机制——顺带给"网卡为什么叫 end0 不叫 eth0"这个第 07 章的老朋友一个正式收尾;
  • 为什么值得:MAC 钉死之后,板子每次上电都以同一个身份出现,交换机、DHCP、IP 白名单从此都省心。半小时的活,性价比极高;
  • 什么算做成:重启几次,ip link 里 end0 的 link/ether 始终是同一个地址。

方向二:JTAG 启动模式(难度:入门)

  • 做什么:跳线切到 JTAG 档,把第 06 章的 OpenOCD 灌注流程直接用作日常启动/救援手段——配置文件就是仓库里的 openocd-z7nano.cfg;
  • 学什么:JTAG 启动的完整姿势——BootROM 在 JTAG 档会空等主机指令,天生就是给调试准备的;
  • 为什么值得(几乎)零成本:硬件天然支持,第 06 章的功夫直接复用。SD 卡刷坏了、BOOT.BIN 写坏了,它就是你的救命通道;Vivado 的 hw manager / xsct 也能干这活,但我们继续用开源工具;
  • 什么算做成:SD 卡完全拔掉,靠 load_image 灌 FSBL + U-Boot,串口照常出现 U-Boot 横幅;
  • 相关章节:第 06 章(JTAG 方法论与灌注命令)。

方向三:PYNQ 镜像尝鲜(难度:入门)

  • 做什么:厂商 demo 包里有现成的 PYNQ 镜像,解包取镜像、写卡启动,不需要自己构建;
  • 学什么:PYNQ 那套"用 Python 驱动 FPGA"的路线,和本手册"底层全手工"的路线正好互补——感受一下两种哲学的差别;
  • 为什么值得:拿来主义,零门槛。玩过之后再决定要不要深入,沉没成本极低;
  • 什么算做成:PYNQ 镜像跑通厂商自带的入门例程,在浏览器里和板子愉快交互。

方向四:响亮 FSBL——让启动过程开口说话(难度:中等)

  • 做什么:取 Xilinx embeddedsw(xilinx-v2018.3 tag)的 FSBL 源码 + 厂商 hdf 里解出的 ps7_init.c,打开 FSBL_DEBUG_INFO 编译开关,用 arm-none-eabi 裸机工具链手工重编一个"话痨版" FSBL(前置:需先 apt 安装 gcc-arm-none-eabi——裸机工具链,与主线的 gnueabihf 是两把扳手);
  • 学什么:FSBL 内部流程(第 02 章的理论在这里落地)、debug 开关的编译机制、ps7_init 寄存器参数与板级硬件的对应关系;
  • 为什么值得:厂商的 FSBL 是"哑巴版"(debug 打印被编译关闭),串口全程静默——第 06 章深夜排雷的一半痛苦都源于此。换了响亮版,启动卡在哪一步直接打印在串口上,所有静默故障无处遁形。这也是理解 Zynq 启动机制最深的一条路;
  • 什么算做成:上电后串口第一屏就有 FSBL 的版本号与分区加载打印;
  • 相关章节:第 02 章(FSBL 职责与 image_mover 流程)、第 06 章(它替你省掉的排雷功夫)。

方向五:QSPI 启动(难度:中等偏上)

  • 做什么:给两棵设备树(内核 + U-Boot)加 QSPI 分区表,U-Boot 增加 QSPI bootcmd,把启动链写进板载 QSPI 闪存——好消息是我们的内核设备树里 qspi 节点已经 status okay,起点不算低;
  • 学什么:QSPI 闪存的启动链布局、U-Boot bootcmd 定制——比 SD 启动更接近"产品化"的形态;
  • 注意:这块板的 QSPI 容量只够放启动链,rootfs 仍要走 SD 卡,所以做出来是"无卡不完整启动"状态——动手前想清楚这是不是你想要的;
  • 什么算做成:拔掉 SD 卡上电,仍能走到 U-Boot(内核与 rootfs 阶段再把卡插回);
  • 相关章节:第 02 章(启动介质与 BOOT.BIN 布局)。

方向六:PL 开垦——FPGA 逻辑篇(难度:进阶)

  • 做什么:安装免费的 Vivado ML Standard(安装时只勾 Vivado + Zynq-7000 器件族,可控制在约 15GB 下载),跟厂商教程 Part1 逻辑篇入门;之后可以把 PL 比特流打进 BOOT.BIN 第三分区,上电自动配置 FPGA;
  • 学什么:FPGA 逻辑设计、PL 与 PS 的协同——这才是 Zynq 姓"F"的那一半,也是买这块板而不是买普通 ARM 板的理由;
  • 注意:全新领域,且必须上 Vivado——Yosys/nextpnr 不支持 Zynq-7000 SoC 流程,没有开源替代。好在纯 PS 移植(本手册的全部)不需要它;
  • 什么算做成:跑通厂商逻辑篇教程的第一个实验;再进一步,把比特流打进 BOOT.BIN 第三分区,上电自动配置 PL。
怎么选?

想继续深耕 Linux/系统侧:一 → 二 → 四 → 五,层层递进;想摸 FPGA:直接六,PYNQ(三)可以当甜点;只想让板子"规矩点":做一个就收工。都不想做?把本手册再通读一遍查漏补缺,也很好。

8.2 附录 A:code/ 代码索引

仓库 code/ 目录下的 9 个文件,全部在实战中验证过——不是示例代码,是当天真用过的那批。索引如下:

文件用途关键点(行号为文件内位置)
uart.py 串口助手:probe / send / listen 三种模式 L11 用 /dev/serial/by-id/ 稳定路径定位 CH340;L51-57 断线自动重连;listen 模式耐心等待设备重新出现
make-bootbin.py BOOT.BIN 打包器(v2,正确版) L63 分区头校验和是 XOR 0xFFFFFFFF(不是减法);L66 结束标记 15×0 + 0xFFFFFFFF(不是全 0xFF);L23-28 布局常量(p2 数据起始 0x19740)
make-sd.sh 制卡脚本:安全检查 + 分区 + 格式化 + 拷贝 L15-17 安全检查(拒 NVMe、要求 RM=1 可移动,L16 的 tr -d ' ' 去前导空格);L22-26 sfdisk 分区表;L38 FAT 分区用 cp -r(FAT 无属主,cp -a 会报错)
zynq-z7-nano-kernel.dts 内核设备树(Linux 6.18 用) L18-23 aliases 把 serial0 指向 uart0;L25-28 内存 512MB;L45-54 gem0 + RTL8211F PHY(MDIO 地址 1、复位脚 MIO46)
zynq-z7-nano-uboot.dts U-Boot 设备树 与内核版同源小改(基于 zynq-zed.dts):控制台 uart0、512MB DDR、同一颗 PHY 描述
openocd-z7nano.cfg JTAG 调试配置(OpenOCD) 四行搞定:um232h.cfg(FT232H)+ 速度 2000 + zynq_7000 目标,全程不需要 Xilinx 工具
extlinux.conf distro boot 启动描述 kernel /zImage + fdt /zynq-z7-nano.dtb + append(console=ttyPS0、root=mmcblk0p2、earlycon)——换内核不用重编 U-Boot 的关键
10-eth.network systemd-networkd 网络配置 Match 段同时写 eth0 与 end0 两个名字——新旧内核命名都兜住
failed-bootgen-mkbootimage.bif 失败案例存档 mkbootimage 路线的"遗照":它的输出被 BootROM 拒收,ELF 节区编码也不合 FSBL 裸拷贝语义,留档示警

两个高频用法示例

打包 BOOT.BIN(输入厂商模板 + 我们的 u-boot 平铺二进制):

python3 make-bootbin.py --template 厂商BOOT.BIN --uboot u-boot-dtb.bin \
  --text-base 0x04000000 -o BOOT.BIN

制卡(第一个参数是 SD 卡设备,第二个是 BOOT.BIN 路径):

sudo ./make-sd.sh /dev/sdX BOOT.BIN
拿去就用之前
  • make-sd.sh 顶部的 SD_DIR / ROOTFS 是绝对路径,改成你自己机器上的实际位置(sudo 下 ~ 会展开成 /root,别用波浪号);
  • uart.py 的 by-id 路径以你机器 ls /dev/serial/by-id/ 的实际输出为准;
  • make-bootbin.py 的 --text-base 必须与你 U-Boot 的 TEXT_BASE 一致(默认 0x04000000)。

8.7 结语:从这里出发

到这里,你已经(或者即将)完整走过一次 Zynq 主线移植。整个移植收敛成六步,贴在这里作最后一眼回顾:

  1. apt 装交叉工具链与依赖(第 03 章);
  2. 编三件套:主线 U-Boot、Linux 6.18 内核、Debian 13 rootfs(第 04 章);
  3. python3 code/make-bootbin.py 生成 BOOT.BIN(厂商模板 + u-boot-dtb.bin);
  4. sudo code/make-sd.sh /dev/sdX BOOT.BIN 制卡;
  5. 插卡、跳线 SD、上电——静默约 3 秒(FSBL)后 U-Boot 横幅,经 extlinux 进内核,到 z7nano login: 约 30 秒;
  6. root/root 登录,end0 配静态 IP(配置文件已内置;若插进有 DHCP 服务器的网络则会自动获取),ssh root@192.168.1.10 收工。

六步之外的一切——BOOT.BIN 的字节布局、JTAG 的 PC 速查表、17 个坑——都是为"第五步没有出现登录提示"的那天准备的。这套东西真正的价值是方法论:换一块板、换一颗 SoC,跳线、启动链、设备树、JTAG 这套分析框架照用,变的只是参数。

剩下的路在 8.1 的路线图里。挑一个方向,继续折腾;折腾出来的新坑,欢迎按本手册的格式记录下去——"症状、定位、修复",这六个字就是嵌入式排障的全部家当。
