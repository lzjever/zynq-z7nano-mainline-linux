CHAPTER 05

制卡与首次启动

第 4 章的三件套装进一张 SD 卡,然后见证三十秒——从一片静默到登录提示。

本章五件事:定好 SD 卡布局、生成 BOOT.BIN、写好 extlinux.conf、用脚本制卡、上电看它跑起来。全程只需要一个 USB 读卡器。第一次制卡建议完整读一遍;以后重制,直接跳 5.5 跑脚本即可。

5.1 目标布局:一张卡,两个分区

Zynq 的 SD 启动布局非常朴素:第一个分区 FAT32 给引导文件,第二个分区 ext4 装整个 Debian。目标长这样:

SD 卡(整卡)
┌─────────────────────────────┬──────────────────────────────────────┐
│ p1:512MB FAT32(类型 0x0C)  │ p2:其余全部 ext4                      │
│ 起始扇区 8192(即 4MB 处)  │ 起始扇区 1056768                     │
│ 卷标 ZNANOBOOT              │ 卷标 rootfs                           │
│                             │                                      │
│  BOOT.BIN     ← ROM+FSBL+U-Boot(5.3 节生成)                     │
│  zImage                     │  一整棵 Debian 13(第 4.4 节 rootfs) │
│  zynq-z7-nano.dtb           │  其中 /lib/modules/6.18.0/ 是模块树(版本号以你的构建为准,见第 4 章)  │
│  extlinux/extlinux.conf     │                                      │
└─────────────────────────────┴──────────────────────────────────────┘

两个数字解释一下:

参数值为什么
p1 起始扇区8192(=4MB)分区表本身占开头几十个扇区;8192 是传统的安全起点,让分区按 4MB 边界对齐,兼顾兼容性与读写性能
p1 大小1048576 扇区 × 512B = 512MB引导文件总共二十几 MB(BOOT.BIN 十来 MB + zImage 约 11.7MB),512MB 绰绰有余,还留够了以后放多个内核试验的空间
p1 类型0x0C(FAT32 + LBA)Zynq BootROM/U-Boot 认的标准 FAT32 类型
p2 起始扇区10567688192 + 1048576,紧接 p1 结尾,一个扇区不浪费

卡的容量不挑:8GB、16GB、32GB 都行——p2 会自动吃掉全部剩余空间,引导文件在 p1 里怎么都够放。

引导文件为什么放 FAT32?因为启动链里每一级都认 FAT——BootROM 内置的是"只够找到 BOOT.BIN 一个文件"的极简只读 FAT(所以文件名、所在分区和目录都是约定死的),U-Boot 则是完整 FAT 驱动,而且 FAT 在 Windows/Linux 上都能直接读写——换内核、改配置,拔卡插电脑就行,不需要任何工具。

再从"谁读哪个分区"的角度看一遍这张卡,启动链立刻立体起来:

BootROM + FSBL:在第一 FAT 分区根目录定位 BOOT.BIN 文件,按第 02 章的 BOOT.BIN 格式解析加载
↓
U-Boot:挂 p1(FAT32),读 zImage、dtb 和 extlinux/extlinux.conf
↓
Linux 内核:按 root= 挂 p2(ext4),从此住在 Debian 里

5.2 备齐 p1 的启动文件

第 4 章已经把 zImage 和 dtb 拷进了 ~/zynq-mainline/sd/boot/,本章再补两样:BOOT.BIN(5.3 节)和 extlinux.conf(5.4 节)。凑齐后 p1 目录结构是:

~/zynq-mainline/sd/boot/
├── BOOT.BIN              # 5.3 节生成
├── zImage                # 第 4.3 节产物
├── zynq-z7-nano.dtb      # 第 4.3 节产物
└── extlinux/
    └── extlinux.conf     # 5.4 节写入

制卡之前用一条命令自查,四样缺一不可:

ls -l ~/zynq-mainline/sd/boot/ ~/zynq-mainline/sd/boot/extlinux/
# 应看到 BOOT.BIN、zImage、zynq-z7-nano.dtb、extlinux/extlinux.conf 四个名字

四个文件正好对应启动链的接力棒,谁接哪一棒:

文件接力棒交给谁
BOOT.BINBootROM 读入 → FSBL(初始化硬件)→ U-Boot 起跑
extlinux.confU-Boot 的 distro boot 按它决定加载什么
zImage + dtbU-Boot 装进 DDR 后跳转,交给 Linux 内核
(p2 的 rootfs)内核挂载,systemd 接最后一棒

5.3 生成 BOOT.BIN:make-bootbin.py

步骤 · 先备齐厂商物料

打包器需要一件输入:厂商原厂 BOOT.BIN(当模板)。来源(出厂 SD 卡;或厂商资料包"开箱测试 images"目录里通常有同款),另有一批补充物料建议一并备齐:

  1. 出厂 SD 卡:插到读卡器,拷出来,顺手做个全卡备份更保险: 
    mkdir -p ~/zynq-mainline/vendor
cp /media/$USER/*/BOOT.BIN ~/zynq-mainline/vendor/   # 挂载路径以实际为准
# 可选的保险:整卡镜像备份(约 10 分钟)
# sudo dd if=/dev/sdX of=~/factory-sd.img bs=4M status=progress
  2. 补充物料(来源 1 拿不到、或第 6/8 章需要时):厂商资料包(向板卡厂商/客服索取;本项目为 Z7-NanoR20-7020-2018.3 系列)demo 压缩包里有现成的 zynq_fsbl.elf 与 hdf,解到 vendor/ 备用(注意 -o 后用 $HOME 而非 ~,波浪号在参数里不展开): 
    7z e 厂商资料包.7z -o$HOME/zynq-mainline/vendor "*zynq_fsbl.elf" "*.hdf"

还记得第 2 章的 BOOT.BIN 布局吗?ROM 头 + 镜像头 + 分区头表 + FSBL 数据,后面才是 U-Boot 分区。我们的策略是模板复用法:拿厂商出厂 SD 卡里的 BOOT.BIN,截取前 0x19740 字节充当模板(ROM 头、镜像头、FSBL 分区连同里面的 ps7_init 板级参数,原封不动——FSBL 携带每板不同的硬件参数,能复用就不重编,道理见第 2 章),只把第二分区换成自己编的 u-boot-dtb.bin:

cd ~/zynq-mainline
python3 手册仓库路径/code/make-bootbin.py \
    --template vendor/BOOT.BIN \
    --uboot    build/uboot/u-boot-dtb.bin \
    --text-base 0x04000000 \
    -o sd/boot/BOOT.BIN

四个参数:

参数含义
--template厂商原厂 BOOT.BIN(出厂卡 FAT 分区里那份;厂商资料包里也有)——提供 ROM 头 + 能用的 FSBL
--uboot我们第 4 章编的平铺二进制 u-boot-dtb.bin
--text-baseU-Boot 的链接地址 0x04000000,必须与分区头的 dest_load/dest_exec 一致(默认值就是它)
-o输出文件,直接落到 sd/boot/ 里

脚本跑完先做"自验证"——重读刚写出的分区头,断言 XOR 校验和与结束标记都正确,然后打印一行 OK(字节数取决于你的 U-Boot 大小):

OK: BOOT.BIN (1217352 字节)  p2=1113096B @0x19740  base=0x04000000

看到 OK 就说明格式三要素(平铺 p2、XOR 校验和、15×0 + 0xFFFFFFFF 结束标记)都过关了。为什么这么讲究?第 2 章的血泪考古和第 7 章的 mkbootimage 失败案都是前车之鉴——BootROM 和 FSBL 对格式的挑剔程度远超文档描述,多一道断言多一分安心。

为什么不用现成的打包工具?

社区常用的 antmicro zynq-mkbootimage 我们实测过:它的输出被 BootROM 直接拒收(第 6 章 JTAG 实测 PC 停在 ROM 错误循环);即使过了 ROM 这关,它对 ELF 分区做"节区块编码",与 FSBL 的裸拷贝语义也不相符。这才有了自写打包器。

由此沉淀的方法论:自制镜像要过三关——逐字节对照已知好样本(厂商 BOOT.BIN)、解剖器验证、真机 JTAG 验收,三者缺一不可。

生成的 BOOT.BIN 直接落在了 sd/boot/ 里(5.2 节的目录就此凑齐);厂商模板建议留个只读副本,以后重打包还要用:

cp vendor/BOOT.BIN vendor/BOOT.BIN.orig    # 模板留底,永远有退路

5.4 extlinux.conf:四行启动菜单

U-Boot 的 distro boot 约定:到各启动介质上找 /extlinux/extlinux.conf。这个文件就是内核启动菜单,我们这份全文只有四行。注意路径和文件名是约定死的,一个字母都不能错(路径与文件名按约定原样书写;顺带一提,BOOT.BIN 的大小写不敏感是 BootROM 的特性,这里没有这层宽松):

mkdir -p ~/zynq-mainline/sd/boot/extlinux
cat > ~/zynq-mainline/sd/boot/extlinux/extlinux.conf <<'EOF'
label Debian trixie (mainline 6.18) — Z7-Nano
    kernel /zImage
    fdt /zynq-z7-nano.dtb
    append root=/dev/mmcblk0p2 rootwait rw console=ttyPS0,115200 earlycon=cdns,mmio,0xE0000000
EOF

逐行拆解:

行含义
label …菜单标题,只在 U-Boot 列菜单时显示,内容随意
kernel /zImage内核镜像路径(相对 FAT 分区根)
fdt /zynq-z7-nano.dtb设备树 blob;U-Boot 把它加载后连同内核一起交给内核——就是第 4 章那棵内核版设备树
append …内核命令行,追加给内核的启动参数,见下方逐项

append 里的每个参数:

  • root=/dev/mmcblk0p2:根文件系统在 SD 卡第二分区;
  • rootwait:死等根设备就绪再挂载——SD 的枚举比内核 probe 慢半拍,嵌入式必备,没有它容易卡"Waiting for root device";
  • rw:按读写挂载(要写日志、装软件的系统盘当然得读写);
  • console=ttyPS0,115200:主控制台走 UART0(uart0 设备节点对应的设备名就是 ttyPS0),115200 波特率;
  • earlycon=cdns,mmio,0xE0000000:最早期控制台,专治"内核刚起步就没声音"。
earlycon 是什么?

内核启动的最早期,串口驱动还没 probe,console= 指定的控制台其实"无字可打"——这段真空期输出全靠 earlycon。它的原理简单粗暴:三要素"驱动名,访问方式,寄存器基址"(cdns = Zynq PS UART 是 Cadence IP,mmio = 直接映射内存,0xE0000000 正是 UART0),不初始化、不 probe,拿到地址直接写寄存器输出。

于是内核从解压后的第一条日志就能上串口。若哪天启动卡死,屏幕停在"Starting kernel…"之后再无输出,有没有 earlycon 就是"死在内核前"和"死在内核里"的分界线——再配合第 6 章的 JTAG,几乎没有盲区。

一句话记住分工:console= 管"内核起来之后",earlycon= 管"内核起来之前",两个都配上,真空期最短。

extlinux 机制的真正威力是解耦:以后换内核、改参数,只需改这个文本文件,不用重编 U-Boot、更不用重打 BOOT.BIN。

5.5 制卡:make-sd.sh 逐段讲解

制卡脚本要做的全是危险动作:整盘分区、整盘格式化——所以脚本的前几行反而是全篇最重要的。先看全文:

#!/bin/bash
# Z7-Nano 主线 Linux 制卡脚本
# 用法: sudo ./make-sd.sh /dev/sdX [BOOT.BIN路径]
# 分区布局: p1=512MB FAT32(引导) p2=剩余 ext4(Debian rootfs)
set -e
trap "sudo umount /mnt/sd1 /mnt/sd2 2>/dev/null" EXIT

DISK=$1
BOOTBIN=$2
SD_DIR=/home/percy/zynq-mainline/sd
ROOTFS=/home/percy/zynq-mainline/rootfs

# ---- 安全检查 ----
[ -b "$DISK" ] || { echo "错误: $DISK 不是块设备"; exit 1; }
echo "$DISK" | grep -q "nvme" && { echo "错误: 拒绝操作 NVMe 设备!"; exit 1; }
RM=$(lsblk -no RM "$DISK" | head -1 | tr -d ' ')
[ "$RM" = "1" ] || { echo "错误: $DISK 不是可移动设备(以防误伤系统盘)"; exit 1; }
echo ">>> 目标: $DISK ($(lsblk -no SIZE,MODEL "$DISK" | head -1)),5 秒后开始,Ctrl-C 取消"
sleep 5

# ---- 分区 ----
sudo sfdisk --wipe always "$DISK" <<EOF
label: dos
start=8192, size=1048576, type=c
start=1056768, type=83
EOF
sudo partprobe "$DISK" || true
sleep 1
P1="${DISK}1"; P2="${DISK}2"

# ---- 格式化 ----
sudo mkfs.vfat -F 32 -n ZNANOBOOT "$P1"
sudo mkfs.ext4 -q -L rootfs "$P2"

# ---- 拷贝 ----
sudo mkdir -p /mnt/sd1 /mnt/sd2
sudo mount "$P1" /mnt/sd1 && sudo mount "$P2" /mnt/sd2
sudo cp -r $SD_DIR/boot/. /mnt/sd1/
if [ -n "$BOOTBIN" ]; then
    sudo cp "$BOOTBIN" /mnt/sd1/BOOT.BIN && echo "BOOT.BIN 已装入"
else
    echo "警告: 未提供 BOOT.BIN(第二参数),此卡无法启动!"
fi
sudo cp -a $ROOTFS/. /mnt/sd2/
sudo rm -f /mnt/sd2/usr/bin/qemu-arm-static

# ---- 收尾 ----
sync
sudo umount /mnt/sd1 /mnt/sd2
echo "=== 制卡完成 ==="

第一段:安全检查——脚本的第一美德

任何"写整盘"的脚本都该这样开头。三道闸,一道比一道重要:

  • 必须是块设备([ -b ]):参数传个普通文件路径就直接出局;
  • 拒绝 NVMe:系统盘十有八九挂在 NVMe 上,点名拒绝——哪怕后面检查有疏漏,你的系统盘也活下来了;
  • 要求 RM=1:lsblk 的 Removable 标志,USB 读卡器是 1,内置硬盘/NVMe 是 0。双保险,专防"/dev/sdb 打成 /dev/nvme0n1"这种手滑;
  • 最后 sleep 5:打印目标盘的容量和型号,给你 5 秒反悔的窗口。

里面还藏着一个调试半晚上的小坑:lsblk -no RM 的输出带前导空格,直接 [ "$RM" = "1" ] 永远不相等,必须 tr -d ' ' 剥掉。shell 脚本的经典暗礁。

动手前改两处

脚本顶部的 SD_DIR 和 ROOTFS 是写死的绝对路径——为什么不用 ~?因为脚本要 sudo 运行,sudo 下 ~ 会展开成 /root 而不是你的家目录(第 7 章的坑)。用之前先改成你的实际路径。

第二段:分区与格式化

sfdisk 从标准输入读分区表描述,三行搞定 5.1 节的布局:

  • label: dos:传统 MBR 分区表(Zynq 这一级的启动固件不挑,GPT 没必要);
  • start=8192, size=1048576, type=c:p1,起始/大小/类型全来自 5.1 节的表;
  • start=1056768, type=83:p2 从这里到卡尾。这里有个坑:第二分区必须显式写 start——不写的话 sfdisk 会用默认对齐值,给你切出一个 3MB 的怪分区,rootfs 当场装不下;
  • --wipe always:抹掉盘上所有旧签名(旧文件系统超级块等),避免内核拿着旧残留闹鬼;
  • partprobe + sleep 1:让内核重读分区表,并给 udev 一点反应时间,免得下一行 mkfs 找不到新分区。

格式化则是一行一个分区:FAT32 卷标 ZNANOBOOT,ext4 卷标 rootfs。卷标是给"人"看的——以后 lsblk 一眼认出这张卡。

第三段:拷贝与收尾

拷贝这段有一个反直觉的知识点,值得单独讲:

sudo cp -r $SD_DIR/boot/. /mnt/sd1/    # FAT 分区:必须 -r,不能 -a!
sudo cp -a $ROOTFS/. /mnt/sd2/         # ext4 分区:必须 -a,不能省!

为什么 FAT 分区不能用 cp -a:-a 表示"尽量保留一切"(属主、权限、时间戳),而 FAT 文件系统压根没有属主和 POSIX 权限的概念——cp 尝试保留属主必然失败,报"无法保留所有权";脚本又开着 set -e,任何非零返回直接中止。所以对 FAT 用朴素的 -r。反过来,ext4 分区必须用 -a:rootfs 里有一堆权限敏感的文件(比如 sudo 的 setuid 位),丢了权限系统照样出问题。

收尾三件事:rm -f qemu-arm-static 是把第 4 章的 qemu 解释器最后清一次场(双保险);sync 把页缓存全部落盘——没有它,拔卡瞬间的数据可能还悬在内存里;开头的 trap … EXIT 保证脚本无论正常结束还是中途爆错,挂载点都会被卸载。

贯穿全文的两行防御

值得单独拎出来讲的是脚本开头两行,它们定义了整个脚本的"失败哲学":

set -e                                # 任何一步失败,立刻中止
trap "sudo umount /mnt/sd1 /mnt/sd2 2>/dev/null" EXIT   # 无论如何退出都卸载

set -e 的意思是:制卡这种多步操作,半途失败比失败本身更糟——一张拷了一半的卡插上板子,症状能把人引到九霄云外去。宁可当场停下来,把错误亮在脸上。trap … EXIT 则兜住另一头:即使中止,挂载点也不会遗留,下次重跑不会撞上"目标正忙"。写任何危险脚本,建议把这六行(set -e、trap、安全检查、sleep)当模板抄。

跑起来

讲解完毕,实战两步。先确认设备名:

lsblk -o NAME,SIZE,RM,MODEL,TRAN
# 插上读卡器再跑一次,多出来的那个就是它;RM 应为 1,TRAN 应为 usb
sudo ./make-sd.sh /dev/sdb ~/zynq-mainline/sd/boot/BOOT.BIN
# 输出 "BOOT.BIN 已装入" 和 "=== 制卡完成 ===" 即成功

看到"制卡完成"再拔卡——脚本退出前已完成 sync 和 umount,放心。整个过程就是把卡插读卡器、跑一条命令、等它跑完,越简单的动作越要克制住"中间拔卡看看"的冲动。

中途报错也不慌:脚本是"从头再来"型幂等设计,重跑一遍会重新分区、重新格式化、重新拷贝,不会因为上次的半成品而出错。

5.6 首次启动:预期时间线

卡从读卡器拔下来,插到板上的 SD 卡槽。上电之前,按这个清单过一遍:

上电前检查清单
  1. SD 卡插在板上的卡槽(不是电脑读卡器),金手指朝向正确、插到底;
  2. 启动跳线切到 SD 档(BOOT_MODE 读回应为 5;JTAG 档会让 BootROM 空等,症状就是全静默——最经典的坑);
  3. type-C "UART" 口连电脑(注意不是 JTAG 口);插上它板子就已经通电了——两个 type-C 口的 VBUS 经 OR 二极管汇到主 5V,任一口可独立供电,实测单 UART 口就能完整跑 Linux;
  4. 电脑上先启动串口监听(手册配套的 uart.py:python3 code/uart.py listen 120;用别的工具也行,115200 8N1、无流控);
  5. 监听窗口就位后再上电。
两个串口铁律

监听器必须在上电前启动。启动最初几秒的输出(哪怕是"静默"本身)是判断卡在哪一级的关键证据;事后才开监听,就永远错过了。

拔插 type-C 会让 /dev/ttyUSB 消失。CH340 会从 USB 总线上"干净地"掉线,监听工具直接崩溃——所以工具必须能自动重连(uart.py 就为此而写);另外 type-C 线材接触不良也会造成同样现象且 dmesg 毫无线索,备一根好线,先怀疑线再怀疑软件。

然后按下电源。预期的时间线(节选,版本号、时间戳以你的实际克隆为准):

5.7 登录进去:五连验证

在串口里用第 4 章设置的账号登录(root / root),然后按顺序验证五件事——正好覆盖整条启动链。串口是"最后的安全网",ssh 是日常通道:前者永远在(不依赖网络),后者舒服(全速终端、能传文件),两个都通才算真正站稳:

# 1) 跑的是我们自己编的内核吗?
uname -a
# 期望:Linux z7nano <你的版本号,手册示例 6.18.0> … armv7l GNU/Linux

# 2) 网口存在吗?叫什么名字?
ip link
# 找 end0(4.5 节第二课:为什么不是 eth0)

# 3) IP 配上了吗?(10-eth.network 的静态 IP 应已生效)
ip addr show end0
# 期望看到 192.168.1.10/24

# 4) 能通到电脑吗?
ping -c 3 192.168.1.20
# 电脑侧先配同网段地址,见下面 nmcli

# 5) 从电脑 ssh 进来(比串口舒服得多)
#    电脑上执行: ssh root@192.168.1.10,密码 root

电脑侧(Ubuntu)把有线网卡配到同网段:

nmcli con add type ethernet ifname enp129s0 con-name fpga-board \
  ipv4.method manual ipv4.addresses 192.168.1.20/24
nmcli con up fpga-board
# ifname 换成你电脑的网卡名(ip link 里查)

如果你的 rootfs 没装 10-eth.network,也可以在板上手动配,临时救命:

ip link set end0 up
ip addr add 192.168.1.10/24 dev end0
手动配 IP 的一只暗雷

手动 ip addr add 的地址,一次 systemctl restart systemd-networkd 就会被清掉——networkd 一接管,不属于自己的配置一律扫除。改网络配置前先想清楚"这块网卡现在归谁管":是 networkd(写 .network 文件),还是你手动。两头抢,必有一头失联。

对了,新系统的 ssh 是我们第 4 章装的 openssh-server,现代协议全支持——第 1 章折腾出厂系统时那些 ssh-rsa 兼容配置,在这里统统不需要,直接 ssh root@192.168.1.10。想少打几个字,给电脑的 ~/.ssh/config 加个别名:

Host z7
    HostName 192.168.1.10
    User root
# 之后只需: ssh z7

顺手再验一下第 4 章拷进去的模块树真的就位:

ls /lib/modules/
# 应看到你的内核版本目录(手册示例 6.18.0);依赖索引已生成

五连全绿之后,再顺手看一眼系统的"体检指标",确认内存和存储都如预期:

free -m          # 内存总量应在 479MB 上下(512MB 减去顶端保留区)
df -h /          # rootfs 就是 SD 卡 p2,大小随你的卡
dmesg | grep -i 'renamed\|macb'   # 重温网口改名现场

5.8 加餐:换个内核试试——extlinux 的威力

系统活了,顺手做一个五分钟的实验,体验本章埋的伏笔。假设你改了内核又编了一版 zImage,想让板子用它——不需要重编 U-Boot,不需要重打 BOOT.BIN,甚至不需要拔卡(ssh 进去直接干):

# 在板上(经 ssh),把新内核放到 FAT 分区
cp /path/to/new-zImage /boot/zImage-new
# 在 /boot/extlinux/extlinux.conf 里加一个新条目(编辑器改,或追加重写)
#   label 新内核试验
#       kernel /zImage-new
#       fdt /zynq-z7-nano.dtb
#       append root=/dev/mmcblk0p2 rootwait rw console=ttyPS0,115200 earlycon=…
reboot

重启后 U-Boot 列菜单,倒计时结束默认进第一条;想换回旧内核,把条目顺序调回去即可。这份"改文本文件就换内核"的从容,来自第 4 章那句 BOOTCOMMAND="run distro_bootcmd"——U-Boot 早就把选择权交到了 extlinux.conf 手里。

安全提示:永远保留一个已知能启动的条目在文件里;万一新内核起不来,拔卡插回电脑读卡器,在电脑上把 extlinux.conf 改回来即可救援——这又是 FAT 第一分区设计的红利。

更进一步的玩法(多内核菜单、fallback 条目、甚至 U-Boot 菜单脚本)都建立在这同一个机制上,留给读者探索。

本章小结
  • SD 布局:p1 = 512MB FAT32 @ 扇区 8192(BOOT.BIN、zImage、dtb、extlinux.conf),p2 = ext4 装整棵 Debian;
  • BOOT.BIN 用模板复用法生成:厂商镜像前 0x19740 字节原封不动 + 我们的 u-boot 平铺二进制,make-bootbin.py 自带 XOR 校验和与结束标记断言;
  • extlinux.conf 四行决定内核怎么启,earlycon 保证内核"落地即说话";换内核只改文件、不重编 U-Boot;
  • make-sd.sh 的三道安全闸(块设备、拒 NVMe、RM=1)是对付"手滑毁盘"的最后防线;FAT 拷贝用 -r 不用 -a,ext4 恰好相反;
  • 首启节奏背下来:静默 3 秒 → U-Boot 横幅 → extlinux → 内核刷屏 → 30 秒到 login;监听器永远比电源先就位;
  • 换内核 = 改一个文本文件 + 重启,extlinux 的解耦就是这么从容。
